Current Research Direction

My work on smartphone-based clinical models led me to a broader question: can we verify not only whether a multimodal model is correct, but whether its decision actually depends on the relevant visual evidence?

This motivates a progression from grounding and counterfactual verification to verifiable multimodal post-training, and ultimately to agents that can recognize when the available evidence is insufficient and acquire what is missing.

Research flow: Visual Grounding → Counterfactual Verification → Verifiable Multimodal Post-Training → Active Evidence Acquisition

Agent Designs

Across my work, I have explored agent architectures where model decisions are coupled with verification, adaptive routing, or interaction with an environment. These are four different research problems, not four instances of the same agent: verification, routing, diagnosis, then active evidence acquisition.

Progression: Verification → Routing → Diagnosis → Active Evidence Acquisition

1. Execution-Grounded Text-to-SQL Agent

How do I verify an agent's action?

SQL generation is not reliable when correctness is judged only from the generated text.

Query + Schema→ Generate SQL→ Execute→ Verify→ Retry / Accept

The environment executes candidate SQL; a verifier uses execution and structural feedback to accept or revise the trajectory. The same signals train GRPO/RLVR.

Key idea: connect inference-time verification with training-time reward.

2. Adaptive Agent & Tool Routing

Which agent/tool should act?

A fixed router does not account for query difficulty, tool suitability, latency, or previous outcomes.

Context→ Select Agent / Tool→ Execute→ Observe Reward→ Update Router

Routing is a contextual bandit: the policy learns from online feedback over quality, latency, and retries, instead of static rules or a fixed LLM router.

at = arg maxa UCB(a | xt)

3. LLM Systems Profiler

How do I diagnose the environment/system?

Poor LLM performance can arise from different bottlenecks across compute, memory, communication, and execution.

Telemetry→ Detect Bottleneck→ Diagnose Cause→ Recommend Action

The implemented system organizes GPU and runtime signals into bottleneck diagnoses and actionable recommendations for distributed LLM training and inference.

Direction: extend this from passive diagnostics toward an agent that iteratively tests hypotheses and selects profiling actions.

[code]

4. Evidence-Seeking Multimodal Agent

What should the agent do when evidence is insufficient?

A grounded multimodal model may still receive insufficient or ambiguous evidence.

Observe→ Ground & Reason→ Verify→ Acquire Evidence→ Re-ground→ Decide

Actions: another view · zoom · ask for context · retrieve · predict · abstain.

R = Rtask + λg Rground + λa Racq − λc C(a)

Reward correct grounded decisions and useful acquisition; penalize unnecessary actions.

Research direction: move from verifying available evidence to learning when and how to acquire missing evidence.

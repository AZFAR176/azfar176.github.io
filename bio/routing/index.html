Adaptive Agent & Tool Routing

Which agent or tool should act for the current request?

A contextual bandit learns routing decisions from task context and observed execution feedback rather than relying on a fixed router.

Task Contextquery · state · history
↓
Context Encoder\(x_t\)
↓
Bandit RouterLinUCB / Thompson Sampling
↓
Select Agent / Tool\(a_t \in \mathcal{A}\)
↓
Execute
↓
Observe Feedbackquality · latency · retries
↓
Reward \(r_t\)

\(r_t\) → Update Router → next routing decision

Formulation

\[ x_t=\phi(q_t,s_t,h_t),\qquad a_t\in\mathcal{A} \]
\[ r_t=\lambda_q Q_t-\lambda_l L_t-\lambda_r N_t^{\mathrm{retry}} \]

\(x_t\) is the current routing context, \(a_t\) the selected agent/tool, and \(r_t\) combines task quality, execution latency, and retry cost.

LinUCB selection

\[ a_t=\arg\max_{a\in\mathcal{A}} \left( \hat{\theta}_a^\top x_t + \alpha\sqrt{x_t^\top A_a^{-1}x_t} \right) \]

Key idea: routing is an online learning problem. Successful, efficient executions reinforce routing decisions; poor-quality, slow, or retry-heavy trajectories change future selections.

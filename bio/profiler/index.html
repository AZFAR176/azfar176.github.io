Agentic Systems Profiling

What is causing the current training or inference bottleneck, and what should be inspected next?

The profiler converts runtime telemetry into structured bottleneck hypotheses. An agent can then use these hypotheses to choose additional profiling actions, test competing explanations, and converge on a diagnosis.

Update hypotheses → Diagnose / Recommend

Agentic formulation

\[ h_t \sim P(H \mid o_{1:t}), \qquad a_t = \pi(o_{1:t}, H_t) \]
\[ o_{t+1} = \mathcal{E}(a_t), \qquad H_{t+1} = \operatorname{Update}(H_t,o_{t+1}) \]

Key idea: move from passive telemetry classification to active diagnosis—the agent selects the next profiling action based on competing bottleneck hypotheses and updates its diagnosis from the resulting observation.

The current repository implements telemetry → bottleneck class → diagnosis/recommendation. The hypothesis → action → observation → update loop is the research direction.

1. Execution-Grounded Text-to-SQL Agent

Implemented

How do I verify an agent's action?

Inference verifier circuit

\[C_{\mathrm{schema}}=\operatorname{Retrieve}(q,h,\mathcal{S},\mathcal{J})\]
\[ d_{\mathrm{critic}} =\operatorname{SemanticCritic}(q,h_q,y,\tau_{\mathrm{exec}}) \in\{\textsc{Pass},\textsc{Retry},\textsc{Abstain}\} \]
\[ z_{\mathrm{retry}} =\mathbb{I}\bigl[\neg V_{\mathrm{static}}(y)\lor\neg V_{\mathrm{exec}}(y)\lor(d_{\mathrm{critic}}=\textsc{Retry})\bigr] \]

\(V_{\mathrm{static}}\): parse, schema/alias/join, safety, and format checks. \(V_{\mathrm{exec}}\): sandboxed read-only execution. The critic is schema-free and sees only \((q,h_q,y,\tau_{\mathrm{exec}})\); it does not re-check tables, columns, or joins. Retry diagnostics come from the failing stage (static / execution / semantic). The loop is bounded by \(K\); otherwise the agent clarifies or abstains.

Retrieve→ Generate→ \(V_{\mathrm{static}}\)→ Execute→ Critic
Pass → return · Retry → correct and re-enter · Abstain → clarify

Training reward (not the critic)

\[ R_{\mathrm{raw}}(y)= \begin{cases} g_{\mathrm{exec}}, & R_{\mathrm{exec}}(y)=1\\[4pt] R_{\mathrm{ast}}(y)+R_{\mathrm{ngram}}(y), & \text{otherwise} \end{cases} \]

GRPO uses only the gated execution/AST/\(n\)-gram reward (\(g_{\mathrm{exec}}=3\)). The semantic critic is an inference controller, not a training reward.
